# Прототип: Система скоринга для планирования ремонтной программы

**EAM-система управления активами электрических сетей 0,4–220 кВ**

Интерактивный React-прототип модуля приоритизации объектов по техническому состоянию (ОТС) для формирования ремонтной программы.

Реализован на стеке **React 18 + Ant Design 5 + Vite**.

## Что реализовано в прототипе

### Экран «Рекомендации»
- **Панель фильтров**: по категории приоритета, типу актива (ВЛ/КЛ/ТП/КТП/ПС), классу напряжения, РЭС
- **Статистика**: 4 карточки-метрики (Критичных / Высокий / Средний / В плане) — кликабельные, применяют фильтр
- **Матрица риска 5×5** (ISO 31000): интерактивная тепловая карта, клик по ячейке фильтрует таблицу
- **Таблица объектов**: сортировка по баллу/износу, цветовые полосы прогресса, индикатор блокирующего дефекта

### Боковая панель детализации (Drawer)
- Итоговый балл P и категория приоритета
- **Декомпозиция** по 4 компонентам (D, W, C, T) с весами и прогресс-барами
- Список открытых дефектов с указанием степени, локации, даты
- Результаты испытаний с % отклонения от нормы
- Рекомендация вида ремонта (КР/СР/ТР/ТО) с обоснованием
- Кнопки **«+ В план»** и **«Отложить»** (с модалкой: причина + целевой год)

### Экран «Конфигурация» (Администратор)
- Редактирование весов компонент (wD, wW, wC, wT) с контролем суммы в реальном времени
- Калибровочные константы (D_max, wear_overdue_cap)
- Пороги категорий приоритета
- История изменений конфигурации

## Скоринговая модель

```
P = wD × D + wW × W + wC × C + wT × T    (P ∈ [0; 10])
```

| Компонента | Содержание | Вес |
|---|---|---|
| D | Дефектная нагрузка | 0,40 |
| W | Износ (возраст / нормативный срок) | 0,25 |
| C | Последствия отказа (прокси) | 0,20 |
| T | Результаты испытаний | 0,15 |

Категории: **Критичный** (≥7,5) · **Высокий** (≥5,0) · **Средний** (≥2,5) · **Низкий** (<2,5)

## Деплой на GitHub Pages

### Вариант 1 — через GitHub Actions (рекомендуется)

1. Создайте файл `.github/workflows/deploy.yml`:

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run build
      - uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
```

2. В настройках репозитория: **Settings → Pages → Source: Deploy from branch → gh-pages**

### Вариант 2 — вручную

```bash
npm run build
# Загрузите содержимое папки dist/ в ветку gh-pages
```

> **Важно**: в `vite.config.js` уже задан `base: './'` — это обеспечивает правильные пути на GitHub Pages.

## Нормативная база

- ПУЭ гл. 1.2 — категории надёжности электроснабжения
- ГОСТ Р 55.0.01-2014 (ISO 55000) — управление активами
- ГОСТ Р МЭК 60300-3-11-2019 — ТО, ориентированное на надёжность
- ISO 31000:2018 — структура матрицы риска
